# Make the Lumen compiler canonical

The compiler can rebuild itself through stage 2 and stage 3. These are the
remaining tasks before installed tools use that Lumen-built compiler without
running the JavaScript compiler pipeline.

## Ship the bootstrapped compiler

- [x] Produce native compiler artifacts from the verified stage-3 bootstrap.
  Build Linux and macOS artifacts for supported architectures, publish SHA-256
  hashes, and keep the stage-2/stage-3 equivalence and no-delegation reports
  with each release.

- [x] Package or install the correct native compiler for the host platform.
  Define a stable package layout and platform/architecture selection. Fail with
  a useful unsupported-platform error when no compiler artifact exists.

- [x] Make release artifacts reproducible from the real bootstrap.
  Build each native compiler twice in clean source-only directories, compare
  hashes, and publish only artifacts produced by the Lumen compiler and Clang.

## Remove JavaScript from normal compilation

- [x] Stop `SelfHostedCompiler` from constructing `new Compiler()`.
  Resolve the packaged native compiler first. Do not use the JavaScript
  compiler to populate an empty cache during `lumen emit`, `build`, or `run`.

- [x] Link native programs without the JavaScript compiler backend.
  Replace `seedCompiler.buildExecutable()` with a small Clang driver that uses
  the Lumen compiler's ABI-selected runtime inputs and publishes output
  atomically.

- [x] Keep JavaScript stage 0 behind an explicit recovery command.
  The stage-0 seed may build the first bootstrap compiler for development, but
  normal CLI, package, and release paths must never select it implicitly.

- [x] Move remaining user-facing compiler entry points to the native compiler.
  Update `lmsh`, HTTP/chat helpers, speed tests, example compilation, and any
  other shipped command that still imports `Compiler` for source compilation.

- [x] Give the LSP a native compiler diagnostics interface.
  Add machine-readable diagnostics to the Lumen driver, consume them from the
  LSP, and keep JavaScript parsing only for editor features that have not yet
  moved to Lumen.

## Prove installed behavior

- [x] Add a clean installed-package test with JavaScript compiler sources
  unavailable. Run `lumen emit`, `lumen build`, and `lumen run`; verify that all
  succeed using the packaged native compiler and Clang.

- [x] Add a guard against JavaScript compiler use in production paths.
  Reject imports or construction of `Compiler` from normal CLI and release
  code. Allow it only in stage-0, recovery, differential, and bootstrap tests.

- [x] Make CI exercise released compiler artifacts on Linux and macOS.
  Download or install the produced artifact in a clean directory, compile the
  compiler sources and representative projects, and retain LLVM, binaries,
  diagnostics, and hashes when a job fails.

## Clean up the old bootstrap story

- [x] Remove stale checkpoint and `compilerImage` documentation.
  Update README, the book, support matrix, builtin lists, and bootstrap docs to
  describe source bootstrapping and the explicit JavaScript stage-0 recovery
  path.

- [x] Document the trust chain and reproducible bootstrap commands.
  Explain stage 0 -> stage 1 -> stage 2 -> stage 3, which stage creates release
  artifacts, how equivalence is checked, and how users verify published hashes.
