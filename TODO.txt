# True Self-Hosting Compiler

Goal: the compiler in `compiler/` must parse, check, lower, and emit its own
source. Clang may assemble and link the emitted LLVM. JavaScript may build the
first seed compiler, but it must not participate in stage 2 or later.

### Next typed-IR slice

- [ ] Lower each `TypedIrModule` function body into typed instructions and
  terminators. The new function, block, and value arenas exist; do not add new
  fields to `IrModule` or the program string map.

- [ ] Make the LLVM emitter accept `TypedIrModule` for one function at a time,
  starting with locals, calls, returns, and integer/string literals.

- [ ] Add typed-IR verifier tests for block ownership, value ranges, and a
  terminator on every reachable block.

- [ ] Fix the primary module loader's duplicate relative-import identity. A
  runtime test importing `parser.lm` and `ir.lm` currently reports duplicate
  private `AstProgram`/`TokenArena` types instead of reusing one module.


- [ ] Replace `IrModule` summaries with a complete typed IR.
  Model arbitrary functions, parameters, structs, basic blocks, instructions,
  values, and terminators. Remove the program string map, `irToProgram`, fixed
  `statement0` fields, and AST-to-map compatibility bridge.

- [ ] Lower typed AST to IR generically.
  Cover every operation used by the compiler itself: declarations, calls,
  structs, field access, slicing, assignment, unary/binary expressions,
  conditionals, loops, break/continue, and returns.

- [ ] Implement a Lumen IR verifier.
  Reject invalid types, missing terminators, bad branch targets, malformed
  values, duplicate blocks, and invalid control-flow before LLVM emission.

- [ ] Make the LLVM emitter consume typed IR only.
  Emit arbitrary functions and control flow with deterministic symbol and block
  numbering. Remove token inspection, name guessing, summary-map reads, and
  duplicated legacy emission paths.

- [ ] Complete LLVM type and value lowering for the compiler closure.
  Correctly lower strings, booleans, integers, structs, arrays, Results,
  pointers, calls, slices, comparisons, and mutable locals. Escape and
  deduplicate string globals safely.

- [ ] Emit runtime declarations and link inputs from the ABI registry.
  Select required runtime units from referenced symbols instead of hard-coded
  compiler cases. Run Clang verification on every generated module.

## P4 - Remove the checkpoint and use the Lumen compiler

- [ ] Delete compiler-image mode.
  Remove the `compiler-main` filename switch, both `emitCompilerMain` paths,
  the `compilerImage` builtin, `lumen_compiler_image`, image embedding in the
  JavaScript linker, and all checkpoint-specific tests and documentation.

- [ ] Add a Lumen-native compiler driver.
  Support module loading, diagnostics, LLVM output, Clang invocation, runtime
  linking, exit codes, temporary files, and atomic output publishing. Keep
  Clang as the external machine-code tool.

- [ ] Make stage 2 independent of the checkout's JavaScript compiler.
  Build and test stage 2 in a clean directory containing only the Lumen compiler
  sources, runtime sources, required package metadata, and external tools.

- [ ] Move `lumen emit`, `lumen build`, and `lumen run` to the Lumen compiler.
  Keep JavaScript only as the documented stage-0 seed or recovery compiler.
  Normal user compilation must not execute the JavaScript compiler pipeline.

## P5 - Prove parity and make it canonical

- [ ] Expand differential tests from the subset to the whole supported language.
  Compare JavaScript and Lumen compilers for diagnostics, verified LLVM, native
  output, stderr, and exit status across examples, modules, packages, and
  generated programs.

- [ ] Fuzz every self-hosted boundary.
  Fuzz the Lumen tokenizer, parser, module loader, semantic passes, IR verifier,
  and LLVM emitter. Require termination, structured rejection, deterministic
  output, and Clang-valid LLVM.

- [ ] Test compiler-scale inputs and repeated builds.
  Compile the complete compiler graph repeatedly and under sanitizers. Add
  limits for recursion, memory use, malformed input, deep nesting, and large
  modules.

- [ ] Run the real three-stage bootstrap on Linux and macOS CI.
  Start from a clean checkout, retain stage artifacts for diagnosis, and never
  cache generated compilers or LLVM between stages.

- [ ] Make the Lumen implementation the source of truth.
  Generate release compilers from the real bootstrap, publish reproducible
  build instructions and hashes, mark the JavaScript compiler as stage 0, and
  update the support matrix only after the no-delegation bootstrap passes.
