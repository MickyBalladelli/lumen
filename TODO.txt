# True Self-Hosting Compiler

Goal: the compiler in `compiler/` must parse, check, lower, and emit its own
source. Clang may assemble and link the emitted LLVM. JavaScript may build the
first seed compiler, but it must not participate in stage 2 or later.

Current blocker: bootstrap control-flow semantics and the remaining
compatibility-IR cleanup still need to be completed.

## Still missing for true self-hosting

- [x] Remove `compilerImage` from the compiler path.
  Delete the builtin, the embedded image fallback, and the bootstrap checks
  that let the compiler delegate to a copied LLVM blob.
- [x] Remove the `compiler-main` filename shortcut.
- [x] Make the bootstrap source coverage gate pass.
  The complete compiler-source inventory is now generic: compiler builtins,
  syntax, IR operations, module graph features, and `json` / `unknown` types.
- [x] Finish typed IR lowering and typed LLVM emission.
- [x] Remove the embedded compiler image from stage 1 and later.

## P0 - Make self-hosting measurable

- [x] Add a deliberately failing real-bootstrap test.
  Build stage 1 with JavaScript, use stage 1 to compile the complete
  `compiler/main.lm` module graph into stage 2, then use stage 2 to build stage
  3. Run each compiler against the same positive and negative corpus.

- [x] Make the bootstrap test reject every delegation shortcut.
  Fail if generated LLVM or binaries reference `compilerImage`,
  `lumen_compiler_image`, an embedded compiler image, JavaScript, Node, or a
  subprocess compiler. Also reject behavior selected by the input filename.

- [x] Define deterministic stage equivalence.
  Canonicalize harmless LLVM metadata, then require stage-2 and stage-3 output
  to match. Verify both modules with Clang and compare the linked compiler
  behavior when byte equality is not meaningful.

- [x] Add a compiler-source coverage gate.
  Inventory every syntax node, type, IR operation, builtin, and module feature
  used by `compiler/*.lm`. The real bootstrap cannot pass while any used
  construct falls through an unsupported or fixture-specific path.

- [x] Remove fixture-shaped compiler behavior.
  Delete hard-coded variable names, values, loop bounds, print values, and
  special cases such as `total`, `sum`, `bad`, `5`, and `8`. Lower syntax from
  its structure and types for arbitrary programs.

## P1 - Build a real frontend in Lumen

- [x] Add lossless compiler containers.
  Provide growable typed storage or typed arenas for tokens, AST nodes, types,
  symbols, IR values, blocks, and diagnostics. Stop encoding compiler records
  and collections into delimiter-sensitive strings.

- [x] Replace the bootstrap tokenizer with a complete tokenizer.
  Emit typed tokens with kind, lexeme, literal value, file, offset, line, and
  column. Support the same keywords, comments, strings, numbers, multi-character
  operators, punctuation, and newline termination rules as the primary grammar.
  Report malformed input without reading past the source.

- [x] Replace `AstProgram` counters with a complete typed AST.
  Represent every declaration, statement, type annotation, and expression used
  by the compiler source. Preserve arbitrary nesting and source ranges.

- [x] Replace the two bootstrap parsers with one parser.
  Remove the `parseAst` summary plus `parseProgram` string-map split. Produce
  one typed AST consumed by every later pass, with no fixed statement,
  parameter, function, or nesting limits.

- [x] Add parser recovery and structured diagnostics.
  Collect multiple syntax errors with source ranges and guarantee progress on
  invalid input.

## P2 - Resolve and check programs

- [x] Build a real module graph in Lumen.
  Parse modules separately, resolve canonical relative and Photon paths,
  preserve export boundaries, detect cycles, and load each module once. Stop
  concatenating imported source text and scanning import lines as strings.

- [x] Implement lexical scopes and symbol resolution.
  Resolve declarations, parameters, locals, functions, structs, fields, and
  imports by identity. Handle shadowing and duplicate declarations without
  name-based emitter guesses.

- [x] Port the complete type model needed by the compiler source.
  Check primitives, structs, arrays, nullable values, Results, calls, field and
  index access, slices, assignment, unary and binary operators, and return
  values. Validate every argument, not only the first one.

- [ ] Finish bootstrap control-flow semantics.
  The bootstrap compiler now checks `if` and `while` conditions plus loop and
  switch nesting and break/continue placement. It still needs definite return,
  use before initialization, unreachable-path tracking, and consistent
  assignment across branches and loops.

- [x] Remove the remaining bootstrap shortcut markers from compiler source.

- [x] Make the bootstrap source coverage gate ready.

- [x] Give builtins and externs one typed ABI registry.
  Make the Lumen compiler resolve and type-check runtime functions from the
  same signatures used for LLVM declarations and runtime linking.

- [ ] Preserve module-aware diagnostics through all passes.
  Keep file and range information in tokens, AST, symbols, typed nodes, IR, and
  backend errors. Match the primary compiler's positive and negative corpus.

## P3 - Replace the compatibility IR and emitter


### Next typed-IR slice

- [ ] Lower each `TypedIrModule` function body into typed instructions and
  terminators. The new function, block, and value arenas exist; do not add new
  fields to `IrModule` or the program string map.

- [ ] Make the LLVM emitter accept `TypedIrModule` for one function at a time,
  starting with locals, calls, returns, and integer/string literals.

- [ ] Add typed-IR verifier tests for block ownership, value ranges, and a
  terminator on every reachable block.

- [ ] Fix the primary module loader's duplicate relative-import identity. A
  runtime test importing `parser.lm` and `ir.lm` currently reports duplicate
  private `AstProgram`/`TokenArena` types instead of reusing one module.

- [x] Pre-register every linked declaration before resolving any imported
  field or return types. The type checker now does a declaration-first pass so
  module-linked names like `__lumen.module.*.TokenArena` stop looking unknown.

- [ ] Replace `IrModule` summaries with a complete typed IR.
  Model arbitrary functions, parameters, structs, basic blocks, instructions,
  values, and terminators. Remove the program string map, `irToProgram`, fixed
  `statement0` fields, and AST-to-map compatibility bridge.

- [ ] Lower typed AST to IR generically.
  Cover every operation used by the compiler itself: declarations, calls,
  structs, field access, slicing, assignment, unary/binary expressions,
  conditionals, loops, break/continue, and returns.

- [ ] Implement a Lumen IR verifier.
  Reject invalid types, missing terminators, bad branch targets, malformed
  values, duplicate blocks, and invalid control-flow before LLVM emission.

- [ ] Make the LLVM emitter consume typed IR only.
  Emit arbitrary functions and control flow with deterministic symbol and block
  numbering. Remove token inspection, name guessing, summary-map reads, and
  duplicated legacy emission paths.

- [ ] Complete LLVM type and value lowering for the compiler closure.
  Correctly lower strings, booleans, integers, structs, arrays, Results,
  pointers, calls, slices, comparisons, and mutable locals. Escape and
  deduplicate string globals safely.

- [ ] Emit runtime declarations and link inputs from the ABI registry.
  Select required runtime units from referenced symbols instead of hard-coded
  compiler cases. Run Clang verification on every generated module.

## P4 - Remove the checkpoint and use the Lumen compiler

- [ ] Delete compiler-image mode.
  Remove the `compiler-main` filename switch, both `emitCompilerMain` paths,
  the `compilerImage` builtin, `lumen_compiler_image`, image embedding in the
  JavaScript linker, and all checkpoint-specific tests and documentation.

- [ ] Add a Lumen-native compiler driver.
  Support module loading, diagnostics, LLVM output, Clang invocation, runtime
  linking, exit codes, temporary files, and atomic output publishing. Keep
  Clang as the external machine-code tool.

- [ ] Make stage 2 independent of the checkout's JavaScript compiler.
  Build and test stage 2 in a clean directory containing only the Lumen compiler
  sources, runtime sources, required package metadata, and external tools.

- [ ] Move `lumen emit`, `lumen build`, and `lumen run` to the Lumen compiler.
  Keep JavaScript only as the documented stage-0 seed or recovery compiler.
  Normal user compilation must not execute the JavaScript compiler pipeline.

## P5 - Prove parity and make it canonical

- [ ] Expand differential tests from the subset to the whole supported language.
  Compare JavaScript and Lumen compilers for diagnostics, verified LLVM, native
  output, stderr, and exit status across examples, modules, packages, and
  generated programs.

- [ ] Fuzz every self-hosted boundary.
  Fuzz the Lumen tokenizer, parser, module loader, semantic passes, IR verifier,
  and LLVM emitter. Require termination, structured rejection, deterministic
  output, and Clang-valid LLVM.

- [ ] Test compiler-scale inputs and repeated builds.
  Compile the complete compiler graph repeatedly and under sanitizers. Add
  limits for recursion, memory use, malformed input, deep nesting, and large
  modules.

- [ ] Run the real three-stage bootstrap on Linux and macOS CI.
  Start from a clean checkout, retain stage artifacts for diagnosis, and never
  cache generated compilers or LLVM between stages.

- [ ] Make the Lumen implementation the source of truth.
  Generate release compilers from the real bootstrap, publish reproducible
  build instructions and hashes, mark the JavaScript compiler as stage 0, and
  update the support matrix only after the no-delegation bootstrap passes.
