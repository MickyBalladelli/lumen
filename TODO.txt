# Lumen TODO

Project audit: 2026-06-30

## P0 - Correctness and safety

- [x] Make every compilation use fresh mutable state.
  `Compiler` now creates fresh semantic, type, IR, and backend components through
  factories for every call. Regression tests cover several valid and invalid
  compilations through one compiler/LSP instance.

- [x] Replace source concatenation with a real module graph.
  Local and Photon modules now parse separately, resolve once by canonical path,
  retain file locations, reject cycles, honor package export lists, and expose only
  explicitly imported names while keeping dependency-private names isolated.

- [x] Make the self-host compiler genuinely self-hosting.
  The native compiler now carries its deterministic LLVM image and reproduces it
  without `lumen_exec`, an external compiler, or a seed file. Tests hide stage-1,
  require stage-2 to build stage-3, compare compiler and program output byte for
  byte, and run the stage-3 compiler independently.

- [x] Add runtime bounds and lifetime safety.
  Dynamic array reads, writes, and loops now use checked indices; string indexing
  and slicing reject invalid ranges. Runtime-owned strings, JSON, lists, maps, and
  objects stay valid until exit and are then freed. Native ASan+UBSan tests cover
  safe allocation plus array read/write, string, and slice bounds failures.

- [x] Harden the HTTP and Socket.IO runtime before calling it production-ready.
  Add request/body limits, partial read/write loops, timeouts, canonical-path
  checks, protocol validation, clean shutdown, and concurrent connection handling.
  Fuzz request and WebSocket parsers.

- [x] Harden Photon installs.
  Reject dependency names that escape `.photon/packages`, install through a
  temporary directory, swap atomically only after validation, and keep the old
  install on failure.

- [x] Make `photon.lock` reproducible.
  Read the lock during install, pin Git dependencies to exact commits, verify the
  checked-out commit, and define update/frozen-lock commands. The lock is currently
  rewritten but never used to resolve an install.

## P1 - Compiler architecture

- [x] Finish the expression AST and stop using token-shape heuristics.
  `RawExpression.parsed` is created but ignored by semantic analysis, type checking,
  and code generation. Represent calls, access, assignment, unary/binary operators,
  arrays, structs, match, and await as real nodes.

- [x] Build a real typed IR.
  Current `IRFunction.body` contains AST statements. Lower expressions and control
  flow into typed instructions/basic blocks, validate IR, and make the backend
  consume IR only.

- [x] Split the 3,480-line LLVM emitter into focused lowering modules.
  Separate control flow, values, aggregates, built-ins, debug metadata, and runtime
  ABI declarations. Add small golden LLVM tests for each lowering family.

- [x] Strengthen the type checker.
  Require boolean conditions, prove non-void functions return on every path, reject
  use before initialization, fully validate match arms, and define generic,
  nullable, Result, and collection variance rules.

- [x] Define one built-in/runtime ABI registry.
  Function names and signatures are duplicated across module registry, expression
  inspection, type checking, emitter code, and C. Generate or consume these tables
  from one typed definition and fail when implementations drift.

- [x] Make diagnostics module-aware and recoverable.
  Preserve file/range data through parsing, module loading, IR, and LLVM emission.
  Report multiple diagnostics per run with snippets, notes, and imported-file paths.

- [x] Create a JS/self-host parity matrix.
  Differentially compile every supported feature with both compilers and compare
  diagnostics, LLVM behavior, and executable output. Do not mark a feature complete
  until both paths pass.

## P1 - Runtime and portability

- [x] Support Linux instead of returning silent fallbacks.
  `arg`/`argCount`, crypto, and WebSocket handshake helpers currently return empty
  or zero outside macOS. Implement portable providers or return explicit errors.

- [x] Split `src/runtime/http.c` into real runtime units.
  Headers and implementations now separate system/fs/string/collections/thread/
  crypto/http code. The compiler links only referenced units and their dependencies.

- [x] Replace empty-string and integer error sentinels with typed errors.
  File, environment, crypto, JSON, process, thread, and HTTP operations return
  `Result<T>`, preserving valid empty strings and zero values.

- [x] Remove shell-command execution from compiler internals.
  Compiler and runtime process launches pass argument arrays directly. Paths with
  spaces and shell characters are covered by native and self-host tests.

- [x] Decide and implement the async model.
  Async calls eagerly create native-thread `Task<T>` values. Await blocks,
  cancellation is cooperative for running work, task errors use try/catch, and
  task arguments are copied while pointer-backed storage remains shared.

## P1 - CLI, editor, and distribution

- [x] Ship a normal compiler command.
  The packaged `lumen` binary supports build, LLVM emit, run, `lumen.json`,
  output selection, optimized builds, Clang selection, help, and version.

- [ ] Add an installed-package smoke test.
  Pack to a clean temporary directory, install the tarball, compile and run a
  program, install a bundled Photon package, start an LSP handshake, and verify all
  documented commands. Include `book/install-lumen.md` or remove the broken package
  link to a file excluded by npm.

- [ ] Make LSP compilation use the same module graph as CLI compilation.
  Local imports currently produce `Unknown module` in the editor. Also implement
  `didClose`, debounce/cancel stale diagnostics, report all errors, and isolate
  compiler state per document/build.

- [ ] Add useful language intelligence after correctness.
  Provide go-to-definition, references, hover types, completion, rename, symbols,
  semantic tokens, and code actions from compiler data instead of re-parsing in the
  extension.

- [ ] Make formatting syntax-aware and idempotent.
  Format from tokens/AST rather than line regexes. Add comments, nested literals,
  multiline calls, match/switch, strings containing braces, malformed input, CRLF,
  and format-twice tests.

- [ ] Complete package metadata and release automation.
  Add license, repository, bugs/homepage, Node engine, publish checks, changelog,
  version synchronization with VS Code/LSP, checksums, and reproducible VSIX/tarball
  release artifacts.

## P2 - Tests, docs, and maintenance

- [ ] Add CI on macOS and Linux.
  Run unit, example, negative, bootstrap, package, VS Code packaging, sanitizer, and
  clean-install tests. Cache tools without caching generated compiler outputs.

- [ ] Split the 1,131-line example test runner.
  Create focused suites and helpers so one failure does not hide unrelated results.
  Add direct unit coverage for tokenizer, module loader, semantic analyzer, emitter,
  runtime ABI, CLI errors, and repeated compiler use.

- [ ] Add parser/compiler fuzzing and property tests.
  Assert the tokenizer/parser never hang or crash, formatting is idempotent, invalid

- [ ] Make temporary outputs collision-safe and cacheable.
  `lmsh` and compile flows use basenames in shared build directories. Key artifacts

- [ ] Either wire `CompilerOptions` into behavior or remove it.
  Garbage collector, ownership, target, and safety settings are public placeholders

- [ ] Reconcile documentation with actual behavior.
  README and book disagree about full self-hosting, typed IR, supported bootstrap

- [ ] Reduce the README to a reliable entry page.
  Move language reference, package catalog, benchmarks, compiler internals, and
